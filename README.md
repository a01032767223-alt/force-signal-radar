# 세력 발자국 레이더 (Force Signal Radar)

큰 자금은 조용히 들어오지도, 조용히 나가지도 못합니다. 유동성 제약이 호가·거래량·수급에 반드시 자국을 남깁니다. 이 도구는 그 자국을 6개 채널로 수치화합니다.

세력이 되기 위한 도구가 아니라, **세력의 물량을 받아주지 않기 위한 도구**입니다.

빌드 과정이 없는 단일 HTML입니다. `index.html` 하나만 열면 동작합니다.

---

## 홈 화면에 추가하기

모바일에서 페이지를 열고 브라우저의 "홈 화면에 추가" (iOS: 공유 → 홈 화면에 추가 / Android: 메뉴 → 홈 화면에 추가)를 누르면 앱처럼 아이콘이 생깁니다. `manifest.json`과 `icons/`에 필요한 아이콘이 모두 포함되어 있어 별도 설정이 필요 없습니다.

## 6채널

| 채널 | 계산 방식 | 대상 |
|---|---|---|
| 매집 강도 | 거래량 침체(0.34) + OBV·가격 다이버전스(0.42) + 저점 절상(0.24) | 공통 |
| 호가 허수율 | 근접 5호가에서 사라진 물량 중 체결가가 닿지 않은 비율 | 공통 |
| 분산 경보 | 거래량 상위 25%일의 윗꼬리(0.42) + 음봉비율(0.28) + 종가 하단도(0.30) | 공통 |
| 큰손 수급 연속성 | 외국인·기관 동반 순매수 비율 + 연속일수 + 최근 5일 기울기 | 주식 |
| 대차잔고 증가율 | 20거래일 전 대비 변화 | 주식 |
| 거래소 순입금 | 유입 강도, 미제공 시 대형 체결의 매도 편향으로 대체 추정 | 코인 |

종합 점수는 결측 채널을 가중치에서 제외하고 재정규화합니다. 채널 하나가 죽어도 나머지로 판정합니다.

판정은 매집 → 견인 → 분산 → 이탈 4국면으로 표시되며, 활성 국면은 색이 있는 테두리 박스로 강조됩니다.

## 6채널 종합 판단 — 매수·매도 방향 배지

채널을 하나씩 보면 판단이 어렵고, 매집 근거와 분산 근거가 나란히 뜨면 초보자 입장에서 방향을 정하기 헷갈립니다. 그래서 종합 판단 맨 위에 **매수 우위 / 매도(정리) 우위 / 관망** 셋 중 하나로 명확히 표시합니다.

- 애매한 구간(분산 경계, 신호 충돌)은 억지로 매수·매도로 우기지 않고 정직하게 **관망**으로 표시합니다.
- 방향이 정해졌을 때는 우세한 쪽 근거만 정식으로 보여주고, 반대쪽 근거는 작은 참고 문구로 접습니다. 진짜 신호 충돌(양쪽 다 강하게 잡힐 때)만 양쪽을 동등하게 보여줍니다.
- 면책 문구로 "매수·매도의 최종 결정과 그에 따른 책임은 전적으로 투자자 본인에게 있습니다"를 명시합니다.

## 눌림목 표시

매집·관심이 확인됐다고 바로 사면 고점에 물리기 쉽습니다. 최근 20거래일 데이터로 지금이 "쉬어가는 정상적인 조정"인지 "지지가 무너진 위험 신호"인지 판별해 5가지 상태로 보여줍니다.

| 상태 | 조건 | 의미 |
|---|---|---|
| 고점 경신 중 | 오늘이 최근 20일 중 고점 | 추격매수 대신 조정을 기다리라고 안내 |
| 눌림 관찰 | 고점 대비 하락 2% 미만 | 아직 눌림이라 부르기엔 이름 |
| **눌림목 진행 중** | 조정 중 + 거래량 감소 + 20일선 지지 유지 | 분할 접근을 검토할 만한 자리 — 청록 배너로 강조 |
| 눌림 마무리 신호 | 거래량 동반 반등 캔들 등장 | 조정이 끝나가는 국면일 수 있음 |
| 지지 이탈 | 20일선 하회 또는 하락폭 과다(18%+) | 눌림이 아니라 위험 신호로 별도 경고 |

경과일은 통상적인 눌림 구간(3~10거래일)을 기준으로 한 점(dot) 막대로 표시됩니다.

## 데이터 연결

**코인은 설정이 필요 없습니다.** Upbit 공개 API가 브라우저에서 직접 열립니다.

**국내주식은 프록시가 필요합니다.** 페이지 하단 입력칸에 워커 주소를 넣고 저장하면 됩니다.

```
https://force-radar-proxy.<계정>.workers.dev
```

필수 경로는 `/ohlcv` 하나입니다. 나머지는 있으면 해당 채널이 켜지고, 없으면 그 카드만 사유와 함께 비워집니다.

| 경로 | 응답 | 출처 | 상태 |
|---|---|---|---|
| `/ohlcv?code=005930&count=120` | `[{date,open,high,low,close,volume}]` 오래된순 | Yahoo Finance | 정상 |
| `/orderbook?code=005930` | `{timestamp,asks:[{price,size}],bids:[]}` 또는 배열 | KIS | 정상 (KIS 키 필요) |
| `/trades?code=005930` | `[{ts,price,volume,side}]` | KIS | 정상 (KIS 키 필요) |
| `/investor` | — | KRX | **비활성화** |
| `/short` | — | KRX | **비활성화** |

### 투자자 수급·대차잔고가 비활성화된 이유

KRX 정보데이터시스템이 **2025년 12월 27일부로 회원제(로그인 필수)**로 전환됐습니다. 거래소가 밝힌 사유는 AI 봇의 무단 데이터 수집으로 인한 서버 과부하 방지입니다. 그 결과 비로그인 요청은 세션 쿠키나 파라미터를 아무리 정확히 맞춰도 `LOGOUT` 오류로 차단됩니다.

실제 계정으로 로그인하는 흐름을 연동하는 것도 가능은 하지만, 자동화 봇 접근은 여전히 이용약관 위반 소지가 있고 계정이 차단될 위험이 있어 시도하지 않았습니다. 시세(`/ohlcv`)는 KRX를 완전히 우회해 Yahoo Finance로 대체했지만, 투자자 수급·대차잔고는 KRX가 유일한 출처라 대체할 방법이 없습니다.

## 워커 배포

```bash
cd worker
npx wrangler deploy

# 호가·체결 채널을 쓰려면 (없으면 허수율만 꺼집니다)
npx wrangler secret put KIS_APPKEY
npx wrangler secret put KIS_APPSECRET
```

### KRX가 계속 400(LOGOUT)을 뱉는 이유

처음엔 요청 형식(POST, Referer, 폼 인코딩, 날짜 형식, 표준코드, User-Agent, 세션 쿠키, 리포트별 필수 파라미터) 문제로 보고 하나씩 고쳤고, `/ohlcv`는 실제로 그렇게 해결됐습니다 — 다만 최종 해법은 KRX를 아예 우회해 Yahoo Finance로 바꾼 것이었습니다.

`/investor`, `/short`는 같은 방식으로 고쳐도 계속 막혔는데, 원인은 요청 형식이 아니라 **KRX 정보데이터시스템이 2025-12-27부로 회원제(로그인 필수)로 전환**된 것이었습니다. 봇 트래픽 차단이 명시된 목적이라, 비로그인 요청은 세션·파라미터를 아무리 맞춰도 통과하지 못합니다. 그래서 이 두 경로는 워커에서 즉시 501을 반환하도록 비활성화해뒀습니다 (KRX를 매번 헛되이 두드리지 않기 위함).

혹시 KRX가 다시 정책을 바꾸거나, 직접 로그인 연동을 시도해보고 싶다면 `worker.mjs`의 `/diag` 엔드포인트로 현재 상태를 확인할 수 있습니다.

```bash
curl "https://<worker>/diag?bld=dbms/comm/finder/finder_stkisu&searchText=005930"
```

응답의 `sent`에 실제 전송된 본문이, `cookie`에 세션 발급 상태가, `firstRow`에 KRX가 돌려준 첫 행이 담깁니다.

## 테스트

```bash
npm test              # 엔진 27건 + 통합 46건
npm run test:worker   # KRX 요청 형식 16건
```

통합 테스트는 가짜 프록시 서버를 띄우고 `index.html`의 실제 코드를 그대로 실행합니다. 매집형·분산형·부분 장애·캐시 응답·무응답 서버·요청 취소를 모두 재현합니다.
