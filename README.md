# 세력 발자국 레이더 (Force Signal Radar)

큰 자금은 조용히 들어오지도, 조용히 나가지도 못합니다. 유동성 제약이 호가·거래량·수급에 반드시 자국을 남깁니다. 이 도구는 그 자국을 6개 채널로 수치화합니다.

세력이 되기 위한 도구가 아니라, **세력의 물량을 받아주지 않기 위한 도구**입니다.

빌드 과정이 없는 단일 HTML입니다. `index.html` 하나만 열면 동작합니다.

---

## 6채널

| 채널 | 계산 방식 | 대상 |
|---|---|---|
| 매집 강도 | 거래량 침체(0.34) + OBV·가격 다이버전스(0.42) + 저점 절상(0.24) | 공통 |
| 호가 허수율 | 근접 5호가에서 사라진 물량 중 체결가가 닿지 않은 비율 | 공통 |
| 분산 경보 | 거래량 상위 25%일의 윗꼬리(0.42) + 음봉비율(0.28) + 종가 하단도(0.30) | 공통 |
| 큰손 수급 연속성 | 외국인·기관 동반 순매수 비율 + 연속일수 + 최근 5일 기울기 | 주식 |
| 대차잔고 증가율 | 20거래일 전 대비 변화 | 주식 |
| 거래소 순입금 | 유입 강도, 미제공 시 대형 체결의 매도 편향으로 대체 추정 | 코인 |

종합 점수는 결측 채널을 가중치에서 제외하고 재정규화합니다. 채널 하나가 죽어도 나머지로 판정합니다.

판정은 매집 → 견인 → 분산 → 이탈 4국면으로 표시됩니다.

---

## 데이터 연결

**코인은 설정이 필요 없습니다.** Upbit 공개 API가 브라우저에서 직접 열립니다.

**국내주식은 프록시가 필요합니다.** 페이지 하단 입력칸에 워커 주소를 넣고 저장하면 됩니다.

```
https://force-radar-proxy.<계정>.workers.dev
```

필수 경로는 `/ohlcv` 하나입니다. 나머지는 있으면 해당 채널이 켜지고, 없으면 그 카드만 사유와 함께 비워집니다.

| 경로 | 응답 | 출처 |
|---|---|---|
| `/ohlcv?code=005930&count=120` | `[{date,open,high,low,close,volume}]` 오래된순 | KRX |
| `/investor?code=005930&days=20` | `{foreign:[],inst:[],retail:[]}` | KRX |
| `/short?code=005930&days=30` | `[대차잔고 주수]` 오래된순 | KRX |
| `/orderbook?code=005930` | `{timestamp,asks:[{price,size}],bids:[]}` 또는 배열 | KIS |
| `/trades?code=005930` | `[{ts,price,volume,side}]` | KIS |

## 워커 배포

```bash
cd worker
npx wrangler deploy

# 호가·체결 채널을 쓰려면 (없으면 허수율만 꺼집니다)
npx wrangler secret put KIS_APPKEY
npx wrangler secret put KIS_APPSECRET
```

### KRX가 400을 뱉을 때

KRX JSON 엔드포인트는 요청 형식에 까다롭습니다. 워커는 일곱 가지를 모두 막아두었습니다.

1. **POST 전용** — GET으로 부르면 400
2. **Referer 필수** — `data.krx.co.kr` 도메인이 없으면 봇으로 판정
3. **폼 인코딩 필수** — `application/json`으로 보내면 400
4. **날짜는 숫자 8자리** — `2026-08-12`는 거부, `20260812`만 허용
5. **표준코드 필요** — 개별종목은 `005930`이 아니라 `KR7005930003`
6. **User-Agent 필수** — 런타임 기본 UA는 차단
7. **`bld` 문자열** — 한 글자만 틀려도 400

1~6번은 코드로 해결됩니다. 남는 건 7번인데, KRX가 예고 없이 바꾸기 때문에 진단 창구를 따로 뒀습니다.

```bash
# 지금 쓰는 bld가 살아있는지 확인
curl "https://<worker>/diag?bld=dbms/comm/finder/finder_stkisu&searchText=005930"
```

응답의 `sent`에 실제 전송된 본문이, `firstRow`에 KRX가 돌려준 첫 행이 그대로 담깁니다. `ok:false`면 `detail.body`에 KRX 원문 오류가 400자까지 들어옵니다. 필드명이 바뀌었으면 `worker.mjs` 상단 `BLD` 객체만 고치면 됩니다.

## 테스트

```bash
npm test              # 엔진 27건 + 통합 46건
npm run test:worker   # KRX 요청 형식 16건
```

통합 테스트는 가짜 프록시 서버를 띄우고 `index.html`의 실제 코드를 그대로 실행합니다. 매집형·분산형·부분 장애·캐시 응답·무응답 서버·요청 취소를 모두 재현합니다.

## 배포

`main` 브랜치에 push하면 GitHub Actions가 테스트를 돌리고, 통과해야 Pages에 올립니다. 저장소 Settings → Pages → Source를 **GitHub Actions**로 설정하세요.

## 읽는 법

지표가 높다고 조작이 아닙니다. 정상적인 기관 매매도 같은 패턴을 만듭니다. 특히 허수율은 체결 틱이 없으면 계산 자체를 하지 않는데, 데이터가 부족한 상태에서 억지로 숫자를 내면 무고한 종목이 조작 의심으로 찍히기 때문입니다.

판단 보조로만 쓰시고, 특정 종목의 시세조종 여부를 단정하지 마세요.
